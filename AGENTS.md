# Рабочие договорённости

## Область работы
Подготовка одностраничного русскоязычного лендинга. Содержательного брифа пока нет: не придумывать профессию, услуги, цены, отзывы, контакты, достижения или CTA. Текущая страница — технический стенд, не готовый лендинг. После получения брифа обновить PRODUCT.md и утвердить визуальную концепцию через Taste → Impeccable.

## Стек и команды
- Astro, статический output, TypeScript strict, обычный CSS/SVG, GSAP + ScrollTrigger.
- `npm ci`, `npm run dev -- --host 0.0.0.0`, `npm run check`, `npm run build`, `npm run preview -- --host 0.0.0.0`.
- Не добавлять React, Lenis, SplitText и другие плагины без конкретной потребности.
- Весь контент доступен без JavaScript. Движение только при `prefers-reduced-motion: no-preference`, через gsap.matchMedia с cleanup; в основном transform/opacity. Обновлять ScrollTrigger после загрузки шрифтов и изображений.

## Инструменты
- Локальные скиллы Codex: `.agents/skills/`. Taste Skill (`taste-skill`, name `design-taste-frontend`) — выбор направления; Impeccable — композиция, шрифты, адаптация, критика и полировка. Читать SKILL.md и нужные references перед применением. Явный бриф важнее случайно выбранной стилистики.
- GSAP: `gsap-core`, `gsap-timeline`, `gsap-scrolltrigger`, `gsap-plugins`, `gsap-performance`.
- Встроенный официальный Imagegen — для сложных недостающих растров. Не устанавливать одноимённые npm-пакеты. Перед генерацией просмотреть исходник; сохранять результат в проект, промпт — в docs.
- Использовать имеющийся Playwright MCP для внешнего референса и локального сайта, viewport, скриншотов, прокрутки и reduced motion. Не устанавливать дублирующий браузерный MCP.
- Context7 зарегистрирован в `.codex/config.toml` проекта. Использовать для актуальных Astro/GSAP docs; `npm run docs:check` делает реальный MCP handshake/list/call, отчёт — docs/research/context7.json. Наличие конфигурации не равно проверке подключения в текущем чате.
- Не менять глобальные настройки Codex, других агентов или соседние проекты. Секреты только через окружение; никаких ключей в git.

## Изображения и дизайн
- Оригинал: `assets/Seven-view stylized character model sheet.png`. Никогда не перезаписывать; assets/ хранит исходники отдельно от src/assets/ и public/images/.
- Производные и генерации — src/assets/; промпты и происхождение — docs/research/.
- Сохранять вытянутое узкое лицо, длинный нос, высокий лоб, скульптурную причёску, лёгкую щетину, длинную шею и стройное тело персонажа. Проверять каждую сцену рядом с исходником.
- Референс: https://www.icapital.es/; наблюдения и скриншоты — docs/research/. Переносить принципы глубины и сцен, не чужие тексты/логотипы/изображения.
- Стиль магазина «собери станок» и WordPress к этому проекту не относятся.

## Проверка и публикация
- Перед сдачей: check + build, production preview, скриншоты телефона 390×844, ноутбука 1366×768 и широкого экрана 1920×1080. Проверять начало/середину/конец, загрузку изображений, консоль, клавиатуру, отсутствие horizontal overflow, reduced motion и работу без JS.
- Проверять сборку и загрузку из вложенного GitHub Pages base, а не только `/`.
- Astro assets импортировать; public assets и внутренние пути строить через import.meta.env.BASE_URL. Site/base вычисляются из PAGES_SITE/PAGES_BASE; workflow передаёт данные configure-pages.
- GitHub Actions: CI при push/PR; публикация только вручную workflow_dispatch после отдельного поручения. Не push/deploy без запроса.
- В отчёте разделять: установлено, зарегистрировано, действительно вызвано, проверено визуально, заблокировано.
